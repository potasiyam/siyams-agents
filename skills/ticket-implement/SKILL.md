# Ticket Implement

Read the linked issue, its comments, and any referenced decisions through the available tracker. Record the issue ID, the requested outcome, and who owns each dependency. If the tracker is inaccessible, use an extract supplied by the user and identify any missing context.

Resolve the repository from the issue links or the user's project map. Inspect its instructions, current branch, working tree, and relevant callers. Turn each acceptance criterion into a check. Present the smallest implementation plan for approval if the user has yet to approve it.

Implement within that scope. Verify the normal entry point, inspect the diff, and report results against each criterion. Use the team roles when the work benefits from independent planning or review. Treat publication, tracker updates, and deployment as separate actions requiring their own authorization.
